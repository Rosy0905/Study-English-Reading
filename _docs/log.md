### 26/10/04

今天从 e 版推到 p 版，八个版本，核心是批注系统的笔迹丢失与残留。

（46）存储加固：mark-engine 改为**每笔立刻落盘**（去掉 300ms 防抖）。根因是刷新/切页靠 `beforeunload` 的异步事务保存，部分浏览器卸载前会掐断事务，笔迹就没了（她实测电脑和平板刷新都消失）。另修`clearActive` 只会清一张纸（刷新后 `activeKey` 为空、回退到第一张常是空的文章页，表现为「点清空清不掉、得画一笔才清掉」）、`redraw` 单条笔迹异常拖崩整张画布。平板模拟下无法复现丢笔，这些是针对性加固，最终以真机为准。

（47）平板自检面板（ink-debug.js，页面内可开）：显示画布显示高 / 内部高 / DPR / 墨迹像素数 / 最下端 y，页面加载后 2.6s 与 6s 各自动报一次，重复错误折叠成 `×N` 不刷屏。加这条是因为平板上报的截图信息不够，必须让她在现场能自查。

（48）荧光笔拉直时长参数改回她明确给过的 450ms（原为 900ms，擅自放宽过）；缩放复位改为从内容实际撑开的高度重算。

（49）修复笔迹「画了却看不到」。关键证据是她的对比：平板 Edge 导出的 JSON 导入电脑火狐空白、导入电脑 Edge 正常——同一份数据两种结果，排除丢笔，指向渲染坐标。根因是归一化坐标乘的 H 用了未就绪的 `clientHeight`，笔迹整片落到画布可视区之外（数据在、像素在，就是不在眼前）。修复：高度改用内容实际撑开的高度，**基准只增不减**（否则内容高度一变，已有笔迹被重新解释成不同位置，表现为笔迹整体挪位、部分看着消失），尺寸不可信时只继续追值不写入基准，图片 load 与字体 ready 后重算并有轮询兜底。

（50）修复画布 resize 的运行时异常：跨作用域引用了不存在的变量导致每 350ms 抛错并中断 resize，而「尺寸不可信」的分支直接返回且没给高度赋值，高度恒为 0，归一化坐标乘 0 导致所有笔迹塌到同一点。修法是把「高度永不为 0」作为硬底线，并新增专测运行时异常的脚本（订阅 `Runtime.exceptionThrown`，断言零未捕获异常、无 "is not defined"、强制把容器压到 0 高时内部高度仍大于 0）。教训是跨作用域引用静态检查查不出来，只有运行时才炸，测试走不到的分支要专门造条件去测。

（51）修复橡皮擦掉其他笔迹。现象是「钢笔画一笔刷新全无、荧光笔画上去直接消失、还把刚画的钢笔一起带走」，决定性线索是荧光笔不该有这能力。根因是 `redraw` 把橡皮排在**最后**重放用 `destination-out` 擦除，于是每次重画（切荧光笔 / 缩放 / 刷新）都把已画好的笔迹擦掉一分，而保存日志完全正常——数据在，渲染时被擦。新增 `replayErase` 让擦除走与实时完全相同的逐段路径，橡皮夹在哪个位置就只擦它之前画的。

（52）定位 t3 笔迹全灭的根因。突破口是解析她的备份 JSON：t3 题目页 119 笔里有 18 条橡皮，擦出范围 −0.142 ~ 0.850（含负坐标，画到画布外），覆盖 100% 的非橡皮笔迹；而 t4 橡皮 0 条。**t4 不是运气好，是她压根没在 t4 用过橡皮。**由此修正两处：橡皮记录的载入处理必须写回库（只改内存的话下次保存又写回去，橡皮一次次复活，这是她「改了还犯」的直接原因）；长按变橡皮恢复 420ms 原手感、荧光笔拉直保持 450ms。

（53）导出改为两页合成单张 PNG：平板浏览器只允许确认一次下载，原先分两次触发必被拦，另给电脑端保留「两页分开导出」。

（54）修复导入不覆盖与缩放鬼影。①导入选文件后确认弹窗不出现：change 事件里没把 input.value 清空，同一文件第二次选不触发。②导入不覆盖：清空数据只删了 IndexedDB、同步备份原封不动留着，紧接着导入「笔迹更少」的旧备份，引擎按「备份比主库新」判定就用旧备份把导入结果整个盖掉。修法是主库时间戳改**按槽位**比（`rec.ts` 是整条记录共用的，文章页落一笔会把全局时间推到最新，题目页的旧备份永远比不过它，平板上丢笔的兜底对题目页失效）。③缩放鬼影：采集分母与渲染基准不一致导致纵向错位。

（55）修复「清空所有数据」被占用时静默失败。`ekzDB.destroy()` 遇到别的标签页占着连接时是 resolve(false) 而不是 reject，而调用方把返回值整个丢弃，于是既不计成功也不计失败——双标签页实测读到了 189 笔却一个库都没删掉、失败列表还是空的。现在接住布尔值，false 记进失败列表，toast 如实提示「被占用，关掉本站其他标签页再试」。

（56）2017t3 题目页淡粉色鬼影定位并清除。鬼影真身是**86 笔 `#fecaca` 荧光笔残留在数据里**，不是渲染故障。三条证据链：截图粉红斜杠实测 `rgb(254,238,239)`，而 `#fecaca` 叠 32% 透明度到白底正是 `rgb(254,238,239)`，一位不差；题目页 197 笔的时序显示橡皮（8 笔）全在末尾，开头 86 笔没有任何橡皮记录——当时屏上擦干净了但擦除动作没存进数据；橡皮能力隔离实测能擦掉 95.8% 的荧光笔像素，功能本身完好。清理后题目页 197 → 111 笔（钢笔 99 / 橡皮 8 / 黄荧光 4 全保留），文章页 78 笔未动。

（57）修复「清空后主页统计还是 3 篇做题页有数据」。根因是 `flush()` 挂在 `pagehide` / `beforeunload` / `visibilitychange` 三个出口上，每次都把**页面内存里的笔迹**原样写回数据库。清空删的是库，而还开着的做题页标签页内存里抱着清空前的笔迹，一切走或一关闭就把旧笔迹写回去。实测复现：清空后立刻 0 条，题目页标签页 flush 一次又变回 1 条。修法是清空时给每条被删记录留一个清空代号（`ekz-wiped-<recId>`，值为清空时刻），做题页落盘前比对内存笔迹的写入时刻，早于代号就判定为旧货、拒绝回写并就地清掉内存与备份。**比对基准不能用 `rec.ts`**——它每次落笔都刷新，会让代号自我解除、旧笔照旧复活；要用 localStorage 里 `ekz-ink-bkts-` 的备份时刻。代号故意不列入清空前缀，它必须在清空后继续活着才有用；清空之后新写的笔时刻晚于代号，不受影响（已加反向验证）。

（58）清空统计口径修正：只有「记录里含 marks」才算批注，笔记页自由笔记单列一类，避免复盘页批注被并进「做题页批注」。
