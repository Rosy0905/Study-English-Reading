# 项目架构与目录说明

本文档说明这个仓库里**每一个文件夹和文件是什么、为什么存在、谁会用到它**。  
面向想改代码、维护内容、或者只是好奇「这堆文件到底在干嘛」的人。

想看「怎么用」请看 [help.md](help.md)，那里是使用者视角。  
想看「改了什么」请看 [log.md](log.md)，那里是改动流水。

---

## 一、这个仓库的整体形态

一个**纯静态网站**，没有后端、没有构建步骤、没有框架。

- 全部功能由原生 HTML / CSS / JavaScript 实现
- 直接双击 `index.html` 就能用，也能挂到 GitHub Pages 上
- **没有打包器**（没有 webpack / vite / npm），改完代码刷新就是最新的
- **没有服务端**，所有数据存在你自己浏览器的 IndexedDB 和 localStorage 里

这一点决定了后面所有的设计取舍：既然是纯静态，就没有服务器帮你编译、  
没有数据库帮你存数据，所以所有逻辑都得写在浏览器端，所有图片都得内嵌或随页带上。

## 三、顶层文件逐个说明

### `index.html` — 主页

整个项目的入口，也是唯一必看的页面。

包含四块东西：

1. **年份卡片列表** —— 2010 到 2026 每年 Text 1–4，卡片上三个入口（做题 / 复盘 / 笔记）
2. **搜索框** —— 按年份或篇目关键词筛卡片
3. **导入 / 导出 / 清空** —— 三个数据管理按钮
4. **最近学习** —— 一排最近点过的篇目卡片

数据全部走 `assets/` 里的模块，页面本身只管渲染。

### `notes.html` — 手写笔记页

单张纸的自由笔记页，**所有篇目共用这一个文件**，靠 URL 参数区分：

```
notes.html?id=2010-text1      # 带 id → 垫上那篇的真题底稿
notes.html                    # 不带 id → 空白纸（自由笔记）
```

底稿图来自 `assets/pdfimg/` 的数据包（不是 `library/` 里的 PNG），原因见第六节。

### `guide.html` — 备考攻略

纯静态文章页，两节：总体规划、做 + 复盘实操教程。和批注系统无关，不会被任何脚本改动。

### `manifest.js` — 篇目清单（最关键的配置）

**整个项目唯一的内容清单文件**，导出一个 `LIBRARY` 对象：

```js
const LIBRARY = {
  2010: [
    {
      id: "2010-text1",
      label: "Text 1",
      zuoti: "library/2010/2010-text1-做题.html",   // 可选，缺了就不显示做题入口
      fupan: "library/2010/2010-text1-复盘.html",   // 可选
      note:  "notes.html?id=2010-text1",            // 全部篇目都有
      underlay: ["library/2010/2010-text1-article.png",
                  "library/2010/2010-text1-question.png"],
      labels: ["文章页", "题目页"]
    },
    // ...
  ],
  // ... 2011 到 2026
};
```

新增篇目只需要改这一个文件 + 把页面文件放进 `library/`。

**重要**：`zuoti` 和 `fupan` 是可选的。目前 68 篇里做题页 38 个、复盘页 35 个，
**整年纯笔记只剩 2022 / 2023 / 2026 三年**。
有 3 篇是「只有做题没有复盘」，已经没有「只有复盘没有做题」的了
——这是内容进度，不是配置错误。

> 数字每次作者更新都会变。下面这份统计是 2026-10-03 的快照，
> 跑 `node scripts/pre-push-check.js` 能看到实时值。

## 四、`assets/` — 全站共用的代码

10 个 JS，约 3500 行，全部是浏览器直接加载的原生代码。

### 核心三件套

| 文件               | 行数  | 职责                                                                        |
| ---------------- | --- | ------------------------------------------------------------------------- |
| `ink-paper.js`   | 642 | **手写纸张引擎**。三处手写（笔记页、做题页批注、复盘页批注）共用这一份，保证手感完全一致。负责笔迹渲染、平滑、长按变橡皮、荧光笔拉直、缩放跟随（荧光笔为方头端点 butt+miter） |
| `ink-toolbar.js` | 651 | **手写工具栏**。可拖动贴边吸附、钢笔 / 荧光笔 / 橡皮、调色盘、粗细滑条（每工具独立记忆）、撤销重做、手指写字开关、隐藏笔迹        |
| `mark-engine.js` | 438 | **批注适配层**。把 `ink-paper` 包成能存能读能撤销的批注系统，并负责「清空后不被旧标签页回写」的守卫 |

**调色盘不在`ink-paper.js` 里，在 `ink-toolbar.js` 的 `PRESET`。**
`pen` 和 `hl` 是两组独立色板各有 16 色，同一个色值在不同工具里是不同的笔 ——  
查「这抹颜色是哪来的」必须去 toolbar 看，光看引擎会认错。荧光笔统一按 32% 透明度渲染，
所以屏上看到的颜色**不等于**色值本身（`#fecaca` 画在白底上是 `rgb(254,238,239)`）。

### 数据层

| 文件          | 行数  | 职责                                                    |
| ----------- | --- | ----------------------------------------------------- |
| `ekz-db.js` | 169 | 笔记数据库统一入口。库名 `ekz-notes-v2`，负责打开 / 读写 / 清空，以及把旧库数据搬一次 |

这个文件存在的意义就是**集中处理 IndexedDB 的坑**：单连接复用、事务 abort、
`deleteDatabase` 被旧连接卡成 blocked。这些坑分散在各处很容易漏，所以统一收口。

> **`destroy()` 的返回约定是 `Promise<boolean>`，被挡时 resolve(false) 而不是 reject。**
> 调用方必须接住这个布尔值。把 `return destroy(name)` 直接透传出去，
> blocked 就会静默消失——既不算成功也不算失败。这是 2026-10-04 修掉的 bug，
> 调用方在 `index.html` 的 `wipeAllData()` 里。

### 导航

| 文件                | 行数  | 职责                                                              |
| ----------------- | --- | --------------------------------------------------------------- |
| `ekz-nav.js`      | 267 | 三页互跳按钮的共用底层 + 位置记忆逻辑。位置记忆用 sessionStorage（只在当前标签页活，刷新保留、关掉自动清空） |
| `ekz-page-nav.js` | 128 | 做题 / 复盘页的自动挂载层。从自身路径反推篇目 id，不依赖 `data-paper` 属性                 |

### 导出

| 文件              | 行数  | 职责                                       |
| --------------- | --- | ---------------------------------------- |
| `ekz-export.js` | 230 | 共享导出弹窗（导入确认、清空确认都走它）。蓝色=导入、红色=清空，样式运行时注入 |
| `ekz-pdf.js`    | 85  | 极简 PDF 生成器，无依赖，每页一张图                     |

### 批注总装

| 文件            | 行数  | 职责                                                                             |
| ------------- | --- | ------------------------------------------------------------------------------ |
| `note-fab.js` | 779 | **做题页和复盘页的总装层**。注入顶栏的「主页 / 阅读模式 / 导出 / 批注模式」按钮，按需加载上面那些模块，负责分栏拖动、双指缩放（仅左栏底图，复盘页右栏解析不做缩放）、复盘页的步骤跟随、右栏有笔记时锁宽防文字回流跑位 |

### 排障工具

| 文件            | 行数  | 职责                                                    |
| ------------- | --- | ----------------------------------------------------- |
| `ink-debug.js` | 126 | 页内自检面板（`window.__ekzDebug`）。显示画布显示高 / 内部高 / DPR / 不透明像素数 / 墨迹最下端坐标 |

> **面板里「墨迹 N」是不透明像素的计数，不是高度**，别当成画布尺寸读。
> 判画布是否被压扁要看 `内部高 / 显示高` 是否等于 `DPR`，而不是看墨迹数。
> 2026-10-04 我在这里读错过一次，凭空推出「画布压扁 14.5 倍」的假结论。

### 加载策略

- **首页和笔记页**：`ekz-db` / `ekz-export` / `ekz-pdf` 直接 `<script>` 加载
- **做题页和复盘页**：固定只加载 `manifest.js` + `ekz-nav.js` + `ekz-page-nav.js` + `note-fab.js` 四个
- **按需加载**：手写引擎、工具栏、导出库都由 `note-fab.js` 在用户点了「批注模式」或「导出」时才拉

这个策略是为了让做题页首屏尽量快 —— 复盘页解析内容多，不加载完不能交互。

### `assets/pdfimg/` — 导出专用底稿数据包（68 个文件，约 100 MB）

每个篇目一个 `.js`，内容是：

```js
window.EKZ_IMGDATA['2014-text1'] = ["data:image/jpeg;base64,...", "data:image/jpeg;base64,..."]
```

**为什么要用 dataURL 而不是直接读 PNG？**

因为 `file://` 协议下，浏览器禁止 JavaScript 读取本地图片文件，  
canvas 会被标记为「已污染」，`toBlob()` / `toDataURL()` 全部报错，导出会直接失败。  
把图转成 dataURL 内进 JS 就绕开了这个限制 —— 这样你**双击打开 index.html 也能正常导出**。

平时浏览页面不会用到这些文件，只有导出时才懒加载。

**这个目录不属于网站运行时**，浏览器不会加载它。是给你（和维护者）用的工具箱。

### 作者批量更新时的正确顺序

作者一口气更新几十篇时（2026-10-03 一次装了 23 篇），按这个顺序走：

```bash
# 1. 先只读盘点，看清哪些是真新增、哪些是重复下载
python scripts/plan-install.py

# 2. 备份
#    cp -r library .backups/pre-update-$(date +%Y%m%d)/

# 3. 复制文件（只复制库里没有的，已有的一律不动）

# 4. 拆复盘页 assets（扫全库，已拆的自动跳过）
python scripts/split-review-assets.py

# 5. 补 manifest
python scripts/sync-manifest.py

# 6. 注入按钮和脚本标签
python scripts/fix-dataroot.py
python scripts/inject-fab.py
#    inject-nav.py 默认只读，要真正写入得直接调它的 patch()：
python -c "import importlib.util;s=importlib.util.spec_from_file_location('n','scripts/inject-nav.py');m=importlib.util.module_from_spec(s);s.loader.exec_module(m);[m.patch(f) for f in m.listPages()]"

# 7. 升版本号破缓存（注意：新注入的 note-fab 标签可能漏网，要抽查）
python scripts/bump-version.py 20261003g
#    bump 只管 assets/*.js?v=，manifest.js?v= 那半边它不管。
#    跑完务必全库 grep 一次确认只剩一个版本号：
grep -o '?v=[0-9a-z]*' library/*/*.html index.html notes.html guide.html assets/*.js \
  | sed 's/.*?v=//' | sort | uniq -c

# 8. 重生成导出数据包（需要 Pillow）
python scripts/make-imgdata.py

# 9. 验证
node scripts/pre-push-check.js
node scripts/test-navlinks.js
```

**三条铁律**：

- **已有的页面一律不要覆盖。** 尤其是复盘页 —— 库里那份已经被 `split-review-assets.py`
  拆过（4.8MB → 850KB），用作者原始的覆盖回去等于把优化拆了。
  判断新旧要用**内联脚本的内容指纹**比，不能比整个文件（我们注入的标签会造成假差异）。
- **`inject-fab.py` 必须排在 `patch()` 前面，顺序不能反。** `patch()` 拿 note-fab 标签
  当插入点，页面里没有它就返回 `no-fab-tag` **静默跳过、不报错**，
  页面看着正常但互跳按钮全都没有。2026-10-03 顺序跑反，8 个新页全被跳过。
- **每一步跑完就检查。** 尤其 `inject-nav.py`：它默认是只读模式，
  加 `--clean` 才会写，但那会连带清理 CSS。作者新装的页面缺三个 script 标签，
  得直接调 `patch()` 才对。

### 批注与数据专项（2026-10-04 新增，都是无头 Edge + CDP）

这批脚本是为排查「题目页鬼影 / 清空无效 / 导出无数据」写的，全部走真实浏览器
双标签页取证，不猜。每个脚本跑完会打印逐条 `OK` / `坏` 和判据数字。

| 脚本 | 查什么 |
| --- | --- |
| `cdp-resurrect.js` | **清空后数据会不会从还开着的做题页标签页复活**。复现 → 修复验证 → 反向验证（新数据不被误拦）一条链走完 |
| `cdp-t3-ghost-final.js` | 鬼影清理后的最终回归。查数据里无残留色、引擎读到的笔数、橡皮仍能擦、画布像素分桶 |
| `cdp-t3-hl-residue.js` | 荧光笔残留三变体对照（含橡皮 / 去橡皮 / 只荧光笔），量化橡皮到底擦没擦 |
| `cdp-erase-truth.js` | 橡皮三种擦法隔离测试 |
| `cdp-ctx-state.js` | canvas 上下文状态审计，看 transform / globalCompositeOperation 有没有被污染 |
| `cdp-export-truth.js` | 导出链路五层对账，确认 payload 里 notes 和 marks 都完整 |
| `cdp-stale-conn.js` | 双标签页连接失效复现，清空时 `deleteDatabase` 被挡的场景 |
| `cdp-t3-question-diag.js` | 题目页坐标基准取证 |
| `strip-fecaca.js` | **数据清理脚本**：只删指定篇目指定槽位里某种颜色的荧光笔，其他一笔不动。跑它之前会先备份 |

> 跑 `cdp-*` 脚本有两件事必须注意：
> **一、必须串行**，CDP 端口会互相占用；
> **二、本地静态服务要真活着**。服务挂掉时 `curl` 可能仍返回 200（那是代理的假响应），
> 实际落进 `chrome-error://`，页面函数全是 `undefined`，跑出来是「假绿」。
> 判法看 `location.protocol` 是不是 http，别只看 HTTP 码。

## 六、`library/` — 内容主体（约 363 MB，565 个文件）

### 命名规律

```
library/<年份>/<年份>-text<N>-做题.html      做题页
library/<年份>/<年份>-text<N>-复盘.html      复盘页
library/<年份>/<年份>-text<N>-article.png    原文底稿图（笔记页垫底）
library/<年份>/<年份>-text<N>-question.png   题目底稿图
library/<年份>/<年份>-text<N>.assets/        该篇的复盘页配图
```

`<N>` 恒为 1–4。

### 三条必须知道的规律

**1. 底稿图永远齐全，做题复盘经常缺**

68 个篇目 = 136 张底稿图（一篇两张），**一张不缺**。
但做题页只有 38 个、复盘页只有 35 个。卡片上缺哪边就不显示哪个入口。

**2. `.assets` 目录只在有复盘页时才生成**

35 个 `.assets` 目录 ↔ 35 个复盘页，一一对应。做题页不需要它。

**3. 做题页和复盘页的图片策略完全不同**

| | 做题页 | 复盘页 |
| --- | --- | --- |
| 图片位置 | **2 张 dataURL 内嵌在 HTML 里** | **0 张内嵌**，全部走 `.assets/` 懒加载 |
| 文件体积 | 1.0 – 2.1 MB | HTML 本身约 850 KB，`.assets` 另计约 4 MB |
| 为什么 | 图和文字必须严格对齐坐标做高亮，内嵌最直接 | 原本也是内嵌，但单文件 4.6–5 MB 首屏太慢，拆成按需小文件 |

`.assets` 里的文件是**伪装成 JS 的 base64 图片**：

```js
window.__ekzA("articleAnnotated","data:image/webp;base64,UklGRk7WBwBXRU...")
```

复盘页自己定义 `window.__ekzA` 收集，滚到哪一步才加载哪一张。

`assets/pdfimg/` 和 `library/*.assets/` **不是同一种东西，别搞混**：

- `assets/pdfimg/` → 为**导出**服务，按篇目集中，JPEG，68 个
- `library/*.assets/` → 为**复盘页提速**服务，按篇目独立，WebP/PNG，356 个

## 八、缓存版本号

所有 `<script src>` 和 `<link href>` 都带 `?v=20261003e` 这样的参数。  
**改完任何 js/css 都要跑**：

```bash
python scripts/bump-version.py 20261003f
```

不跑的话浏览器会一直吃旧缓存，表现是「我明明改了，页面还是老样子」，  
很容易误判成代码没生效。

脚本还会**查漏网** —— 有些引用压根没写 `?v=`（那就等于 URL 永远不变，  
浏览器永远吃缓存），不带参数运行就能看到这些漏网的引用。

`assets/pdfimg/` 下的文件**故意不带版本号**：它们是懒加载拼接路径，加了反而对不上。

## 九、数据存在哪

整个网站没有服务器，数据全在你自己的浏览器里：

| 数据             | 存储位置                     | 生命周期               |
| -------------- | ------------------------ | ------------------ |
| 手写笔记 / 批注      | IndexedDB `ekz-notes-v2` | 长期，清理浏览器数据会没       |
| 笔迹即时备份（平板防丢网） | localStorage（仅最近 3 篇，LRU 淘汰） | 每笔落盘同步写一份，只保正在写的几篇、老篇自动清，通常 <1MB，不挤占同域名其他项目 |
| 收藏 / 学完 / 最近学习 | localStorage             | 长期                 |
| 工具偏好、颜色、粗细、缩放  | localStorage             | 长期                 |
| 位置记忆           | sessionStorage           | **只在当前标签页**，关掉自动清空 |

位置记忆刻意用短命的 sessionStorage，是为了避免第二天回来还停在上周的位置。

**换设备、换浏览器、重装系统，笔迹都不会跟着走**，只能靠导出 JSON 迁移。  
这是纯静态方案的固有限制。

## 十一、几条踩过的坑

给未来要改这块代码的人，也给我自己。

**校验脚本报「全通过」时，先确认它真的查到了东西。**  
写校验脚本时把 manifest 的 `underlay` 当对象处理，统计出来永远是 0，  
等于什么都没验证。看到 0 就要警惕。

**图片纠偏不许批量做。**  
方向和角度必须先看过对比图、确认过再动手，不要凭感觉批量旋转。

**旋转会让画布一角被切掉**（题目页下留白会直接归 0），  
转完必须跟一遍 `normalize-margins.py` 把页脚补回来。

**样式出问题别靠截图猜。**  
直接在页面里读 `getComputedStyle` 和 `style.textContent`，一步定位。

**异步挂载的地方要主动补一次。**  
复盘页正文是它自己同步渲染的，而批注引擎是异步启动的。  
等观察器注册上，DOM 早就稳定了，观察器永远不触发 —— 必须主动调一次。

**IndexedDB 的 `IDBRequest` 自己有一个 `result` 属性且指向自身。**  
在 `oncomplete` 里反查 `result !== undefined` 永远为真，  
读事务必须在 request 的 `onsuccess` 里取 result。

**CDP 测试必须串行跑，端口会互相占用。**  
合成鼠标事件在 canvas 上不可靠，要测画布行为得用页面内 `dispatchEvent`。

**测试里别写死篇目样本。**  
`test-nav.js` 里原本写死 `2017-text4` 当「只有复盘」的样本，
2026-10-03 作者给它装了做题页，它变成「齐全」了，测试直接挂。
现在改成从 manifest 动态挑 —— **以后作者再更新内容，这类测试永远有效**。

**判断页面新旧要比内容指纹，不要比整个文件。**  
我们给页面注入过 script 标签、图标、data-root，
整个文件的 MD5 必然不同。应该只取内联 `<script>` 的内容做指纹。

**`.gitignore` 对已入库文件无效。**  
只影响未跟踪文件。改规则后要配 `git rm --cached <文件>`。

**写新工具前先把旧的读完。**  
2026-10-03 我以为 `split-review-assets.py` 只支持 2025-text2 一页，
动手写了个批量版，写完才发现**原脚本本来就是扫全库的**。
那个废脚本留在 `scripts/_archive/split-review-batch.py` 里当提醒。

**装新页面的顺序不能反：`inject-fab.py` 必须先跑，`inject-nav.py` 的 patch 后跑。**  
`patch()` 的插入点锚在 note-fab 标签之前，页面里没有 note-fab 就直接返回
`no-fab-tag` 静默不写 —— 页面看着正常，但互跳按钮一个都没有。
2026-10-03 我顺序跑反了，8 个新页全被跳过，是 `test-navlinks.js` 报的
「没有按钮」才暴露出来。**这个失败模式不会报错，只会静默跳过。**

**bump-version.py 认不出的标签格式要手工补，但它不检查 `manifest.js`。**  
它只匹配 `assets/*.js?v=`，所以 `manifest.js?v=` 那一半经常漏掉，
跑完还得全库 grep 一次 `?v=` 确认只有一个版本号。

**`patch()` 里不要写死版本号。**  
原来写死 `20261004a`，新装的页就带着旧版本号混进来，
下次 bump 还得再刷一遍。现在改成从页面里已有的 `?v=` 读出来跟着走。

**别拿「点两次 next 一定到第 2 步」当断言。**  
各篇步数不同，2026-10-03 装完 73 页时 `test-posmem-all.js` 整片假挂
（写死 `before === 2`，实际有到第 1 步也有到第 3 步的）。
真正该验的是 `before === after`（刷新后回到原来那一步）。

**「只有复盘没有做题」这类篇目会随作者更新归零。**  
它不能当测试里必须存在的类别，要写成「有就测、没有就跳过」。

**筛选时间戳时别用错下限。**  
作者分几批下载文件，我只按 `20:00` 之后筛，漏掉 20:53 那批 8 个。
按「本次任务开始前的全部新增」来列，不要凭印象定时间阈值。

**返回 `Promise<boolean>` 的 API 必须接住返回值。**  
`indexedDB.deleteDatabase()` 被别的标签页挡住时是 `resolve(false)` 而不是 reject，
`ekzDB.destroy()` 原样透传。调用方只写 `return destroy(name)` 就把这个 false 丢了——
既不计成功也不计失败，界面照跑、toast 照弹，但一个库都没删掉。
2026-10-04 她反馈的「清空全部数据无效」就是这个。

**清空数据要考虑「别的标签页还开着」。**  
删库只动IndexedDB，而开着的做题页内存里还抱着旧笔迹，
`flush()` 挂在 `pagehide` / `beforeunload` / `visibilitychange` 三个出口上，
一切走或一关闭就把旧笔迹写回去。表现是「明明清空了，统计还是 3 篇」。
解法是清空时给每条记录留个代号（`ekz-wiped-<recId>`），
别的页面落盘前比对发现自己手里的笔早于代号就拒绝回写。
**比对基准不能用 `rec.ts`**——它每次落笔都刷新，会让代号自我解除、旧笔照旧复活；
要用localStorage 里 `ekz-ink-bkts-` 的备份时刻。

**自检面板的「墨迹 N」是像素计数，不是高度。**  
2026-10-04 我把它当高度读，凭空推出「画布被压扁 14.5 倍、H 涨到 18604px」，
差点照着这个假结论去改渲染代码。判画布是否变形要看`内部高 / 显示高` 是否等于 `DPR`。

**调色盘在 `ink-toolbar.js` 的 `PRESET` 里，不在 `ink-paper.js`。**  
`pen`（钢笔）和 `hl`（荧光笔）是两组独立色板，同一个色值在不同工具下是不同的笔。
2026-10-04 我因为把荧光笔的色值认成钢笔色，推断鬼影是「钢笔拉的直线」，方向整个错了。
另外荧光笔按 32% 透明度渲染，**屏上看到的颜色不等于色值**
（`#fecaca` 画在白底上是 `rgb(254,238,239)`），对色要用这个公式算，不能直接比 hex。

**写判据要选不会踩自己脚的口径。**  
`cdp-eraser-persist-test.js` 里「擦除生效」判的是 `afterErase < pen1 * 0.75`，
实测 6603 → 5137 = 0.78，刚好卡不过，报了两年假失败。
判据阈值要留余量，或者改成「擦除区像素显著下降」这种相对判断。

**测「清空后还能不能存住新数据」不能只测正向。**  
清空代号如果写得太激进，会把清空之后新写的笔也拦掉。
所以任何「拒绝回写」类修复，都必须配一条反向验证：
清空 → 写入新数据 → 确认能读出来。

**本地静态服务死了，`curl` 可能还返 200。**  
那是被代理拦住的假响应，浏览器实际落进 `chrome-error://`，
页面函数全是 `undefined`，测试跑出来是「假绿」。2026-10-04 我因此白跑了好几轮。
判法看 `location.protocol` 是不是 http、以及页面函数 `typeof` 是不是 function，
别只看 HTTP 状态码。
